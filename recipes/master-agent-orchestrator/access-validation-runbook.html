4. The autonomy boundary (the "no escalation" answer)

Codex acts autonomously only within the orchestrator's PermissionPolicy, which by default allows exactly one command:

python executable + task.py    # [sys.executable, "task.py"]

Anything outside that (network, package installs, other binaries, file writes beyond the run sandbox) is denied until you explicitly add it to the policy. By design That denial is the escalation gate: it is what keeps Codex from doing unreviewed, side-effecting work. To widen autonomy, add a command to the policy only after documenting why it is needed, what it mutates, and what audit evidence it writes.

  • Within policy: Codex runs without you.
  • Outside policy: the orchestrator refuses and records the denial, which is the intended human checkpoint.

Once Chris approves the execution of a specific build, Claude owns the rest: running it to completion and ensuring it operates as intended and safely, without further interaction for in-scope work.
